# Модуль распределенного обмена заказами через XML (1С:Предприятие 8.3)

## Описание проекта

Проект представляет собой готовую интеграционную систему обмена данными между двумя конфигурациями на платформе 1С:Предприятие 8.3 (условные «Центральная база» и «Торговая база»).

В основе решения лежит специализированный транспортный механизм на базе формата **XML (DOM)**, обеспечивающий надежную передачу документов «Заказ покупателя», сквозную синхронизацию нормативно-справочной информации (НСИ) и жесткий контроль неизменности данных после регистрации факта отправки.

---

## Архитектура интеграционного решения

Взаимодействие систем построено на принципах гарантированной доставки и транзакционной целостности данных.

```
 [Центральная база]                           [Торговая база]
   Документ "Заказ"   -->  Экспорт в XML  -->  Загрузка через DOM
       (ExternalID)       (Сериализация)       (Поиск/создание НСИ)

```

### 1. Источник данных: Центральная база (Формирование и экспорт)

Отвечает за первичную регистрацию заказов и подготовку пакетов данных к выгрузке.

* **Документ «Заказ»:** содержит полную аналитику сделки (уникальный `ExternalID`, сквозную нумерацию, дату с точностью до секунды, контрагента и табличную часть со спецификацией товаров).
* **Механизм сериализации:** экспорт данных реализован через объектную модель XML-сериализации платформы, гарантирующую строгое соответствие схемы данных целевой системе.

### 2. Приемник данных: Торговая база (Импорт и обработка)

Реализует логику разбора пакета обмена, поиска сопоставлений в базе-приемнике и создания документов.

* **Чтение через объектную модель DOM:** обеспечивает полный контроль структуры входящего файла, гибкую валидацию узлов и корректное приведение типов (включая приведение строковых дат в формат `Дата` платформы 1С).
* **Синхронизация НСИ:** при импорте строк спецификации система производит безопасный поиск элементов справочников (`Контрагенты`, `Номенклатура`) по ключевым полям с обработкой исключений в случае отсутствия сопоставления (предотвращение появления «битых» ссылок).

## Безопасность и контроль целостности данных

В проекте реализован важнейший для реального бизнеса паттерн **защиты отправленных данных от изменения (Immutable Data)**:

* **Регистр сведений контроля отправки:** при успешном формировании XML-пакета уникальный `ExternalID` документа фиксируется в специализированном регистре.
* **Ролевая модель доступа:** перехвачены события формы и объекта документа `ПередЗаписью()`. Если документ уже был выгружен (зарегистрирован в регистре), интерактивное редактирование и перепроведение для рядовых пользователей полностью блокируется. Изменение доступно только администраторам системы через проверку ролей (`РольДоступна()`), что гарантирует идентичность данных в обеих базах.

## Структура пакета обмена (XML-схема)

Обмен осуществляется в текстовом формате UTF-8 с четкой иерархической структурой данных:

```xml
<Order>
    <ExternalID>123</ExternalID>
    <Date>2026-02-18T14:35:12</Date>
    <Customer>ООО Ромашка</Customer>
    <Items>
        <Item>
            <Name>Монитор</Name>
            <Quantity>2</Quantity>
            <Price>15000</Price>
        </Item>
    </Items>
</Order>

```

## Интерфейс системы

Интерфейс обеих конфигураций оптимизирован под быстрое выполнение рутинных операций:

* **Центральная база:** Форма документа снабжена визуальными статус-индикаторами регистрации выгрузки.
* **Торговая база:** Разработана удобная интерактивная обработка «Загрузка заказов» с логированием результатов импорта на форму в реальном времени.

## Технологический стек

* **Платформа:** 1С:Предприятие 8.3 (Управляемые формы).
* **Работа с XML:** Объектная модель документов (DOM) для чтения, `ЗаписьXML` для экспорта.
* **Слой хранения данных:** Регистры сведений (для контроля блокировок), документы, объектные справочники.
* **Архитектура кода:** Вынос тяжелой логики проведения и разбора XML на сторону сервера в неглобальные Общие модули с повторным использованием значений.

---

## Как запустить проект

1. Создайте две пустые информационные базы 1С.
2. В Конфигураторе базы-источника загрузите конфигурацию `Центральная.cf`.
3. В Конфигураторе базы-приемника загрузите конфигурацию `Торговля.cf`.
4. Обновите конфигурации баз данных (`F7`).
5. Для демонстрации работы сформируйте заказ в первой базе, нажмите кнопку выгрузки, и загрузите полученный файл во второй базе через обработку импорта.
